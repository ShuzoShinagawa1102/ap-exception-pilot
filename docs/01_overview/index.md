# Accounts Payable 例外処理 / 01_overview

    ## ビジョン
    請求書処理を、入力作業からではなく、例外解消オペレーションとして再設計する。

    ## このドメインをどう見るか
    この領域の本質は、**書類やフォームを処理すること**ではない。  
    本質は、**意思決定に必要な正当性・証拠・ルール適合性・責任所在を、期限内に接続すること**である。

    したがって本テーマは、単なる自動化ツールではなく、次の問いに答える業務基盤として捉える。

    - いま何の案件が動いているか
    - その案件はどの規則・契約・証拠に拘束されるか
    - 次に誰が何をすべきか
    - 何が例外で、何が通常か
    - 顧客価値は「処理件数」ではなく、どの結果改善で測るべきか

    ## 対象ドメイン
    AP自動化は進んでも、3-way match 不一致、税区分不備、承認経路逸脱、仕入先マスタ不備、支払保留理由の解釈などの例外処理が最後まで人手に残っている。

    ## 顧客と受益者
    - **一次顧客（予算保持者）**: 大企業経理部、シェアードサービスセンター、BPO、ERP導入企業、POベース購買の強い製造・流通・小売
    - **現場受益者**: 業務担当者、管理者、監査/統制担当
    - **最終受益者**: エンドユーザー、患者、取引先、契約者、発注者など、処理遅延や品質ばらつきの影響を受ける当事者

    ## 顧客が利益を被るメカニズム
    例外解消時間短縮、支払遅延防止、ベンダー問い合わせ削減、承認統制強化、早期支払割引の取りこぼし防止

    重要なのは、「1人の作業を軽くする」だけで終わらないことだ。  
    このドメインでは、遅延や不整合が **売上、資金化、顧客体験、規制対応、監査対応** に波及する。  
    だからこそ、プロダクトの価値は UI の便利さではなく、**業務のボトルネックを外せるか** で決まる。

    ## なぜ10億円級が狙えるか
    IFOL の 2025年調査では、66%が請求書データをERPへ手入力し、63%が週10時間超を請求処理に費やしている。最大の課題は manual data entry と data errors/discrepancies である。[R1] 市場自体も AP automation の成長トレンドに乗っており、成熟した ERP 環境の上で『例外解消』だけを深く取る余地が大きい。[R2]

    ## 主要アクター
    - **買掛金担当**: 請求書受付・照合・支払起票
- **購買担当**: PO/受領の責任者
- **現場承認者**: 費用妥当性や予算承認
- **仕入先**: 請求書発行と問合せ
- **財務統制担当**: 税務・統制・監査要件を持つ

    ## 提供するべきプロダクトの姿
    この領域では、チャットUIや文書要約だけでは不十分である。必要なのは以下を備えた「業務OS」である。

    1. 案件・ケースの集約
    2. ルールと証拠の接続
    3. 例外の検知と優先順位付け
    4. 関係者へのアサインと追跡
    5. 監査証跡と再現性
    6. 学習ループ（過去案件を次回運用へ還元）

    ## 本資料におけるプロダクト方針
    - ドメイン用語を先に定義し、実装詳細は後ろに置く
    - 生成AIは一部機能であり、中心はケース運用と状態管理
    - 既存基幹システムを置き換えるより、**既存システム間の高摩擦部分を支配する**
